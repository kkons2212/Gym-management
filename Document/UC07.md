| **Use Case ID** | **UC07.1.1** |
| :--- | :--- |
| **Tên Use Case** | **Tạo mới tài khoản và phân quyền** |
| **Tóm tắt** | Cho phép Admin tạo mới tài khoản nhân viên trên hệ thống và thiết lập vai trò, quyền hạn truy cập tương ứng. |
| **Dòng sự kiện chính** | 1. Admin chọn chức năng "Tạo mới tài khoản".<br>2. Hệ thống hiển thị biểu mẫu nhập thông tin tài khoản mới và danh sách quyền hạn.<br>3. Admin nhập thông tin tài khoản (tên đăng nhập, email, mật khẩu...) và chọn vai trò/quyền hạn truy cập.<br>4. Admin nhấn nút "Lưu" (hoặc "Hoàn tất").<br>5. Hệ thống kiểm tra tính hợp lệ, lưu thông tin tài khoản mới vào CSDL và hiển thị thông báo "Tạo tài khoản thành công". |
| **Dòng sự kiện phụ** | **5.1. Dữ liệu không hợp lệ hoặc trùng lặp:**<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.1. Hệ thống phát hiện tên đăng nhập/email đã tồn tại hoặc dữ liệu nhập sai định dạng và hiển thị thông báo lỗi chi tiết.<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.2. Hệ thống giữ lại các thông tin Admin vừa nhập trên biểu mẫu.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 3 |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình "Cấu hình Cài đặt & Phân quyền" (mục Quản lý tài khoản). |
| **Hậu điều kiện** | - Tài khoản nhân viên mới cùng phân quyền tương ứng được lưu vào CSDL. |

| **Use Case ID** | **UC 7.1.2** |
| :--- | :--- |
| **Tên Use Case** | **Cập nhật tài khoản và phân quyền** |
| **Tóm tắt** | Cho phép Admin chỉnh sửa thông tin tài khoản nhân viên hiện có và thay đổi vai trò, quyền hạn truy cập. |
| **Dòng sự kiện chính** | 1. Admin chọn một tài khoản cần chỉnh sửa từ danh sách tài khoản.<br>2. Hệ thống hiển thị thông tin chi tiết và cấu hình quyền hạn hiện tại của tài khoản đó.<br>3. Admin thay đổi thông tin tài khoản hoặc điều chỉnh lại vai trò/quyền hạn truy cập.<br>4. Admin nhấn nút "Lưu thay đổi".<br>5. Hệ thống kiểm tra tính hợp lệ, cập nhật thông tin vào CSDL và hiển thị thông báo "Cập nhật thành công". |
| **Dòng sự kiện phụ** | **5.1. Dữ liệu không hợp lệ hoặc trùng lặp:**<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.1. Hệ thống phát hiện email cập nhật bị trùng với tài khoản khác hoặc dữ liệu sai định dạng và hiển thị thông báo lỗi chi tiết.<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.2. Hệ thống giữ nguyên thông tin Admin vừa chỉnh sửa.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 3.<br>**5.2. Vi phạm quyền quản trị:**<br>&nbsp;&nbsp;&nbsp;&nbsp;5.2.1. Admin thao tác tự tước quyền quản trị của chính tài khoản đang đăng nhập. Hệ thống từ chối thao tác và hiển thị thông báo "Không thể tự thay đổi quyền của tài khoản hiện tại".<br>&nbsp;&nbsp;&nbsp;&nbsp;5.2.2. Hệ thống khôi phục lại lựa chọn quyền quản trị ban đầu.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 3. |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình "Cấu hình Cài đặt & Phân quyền" và tài khoản cần sửa đã tồn tại trong hệ thống. |
| **Hậu điều kiện** | - Thông tin tài khoản và phân quyền mới được cập nhật vào CSDL. |

| **Use Case ID** | **UC 7.1.3** |
| :--- | :--- |
| **Tên Use Case** | **Khóa / Mở khóa tài khoản** |
| **Tóm tắt** | Cho phép Admin khóa quyền truy cập của tài khoản nhân viên đang hoạt động hoặc mở khóa cho tài khoản đang bị khóa. |
| **Dòng sự kiện chính** | 1. Admin chọn tài khoản trên danh sách và nhấn chọn chức năng "Khóa" hoặc "Mở khóa".<br>2. Hệ thống hiển thị hộp thoại yêu cầu xác nhận thao tác.<br>3. Admin nhấn "Xác nhận".<br>4. Hệ thống kiểm tra ràng buộc, cập nhật trạng thái tài khoản vào CSDL và hiển thị thông báo thực hiện thành công. |
| **Dòng sự kiện phụ** | **4.1. Vi phạm quyền quản trị (Tự khóa tài khoản):**<br>&nbsp;&nbsp;&nbsp;&nbsp;4.1.1. Admin yêu cầu khóa chính tài khoản đang đăng nhập. Hệ thống từ chối thao tác và hiển thị thông báo "Không thể tự khóa tài khoản đang đăng nhập".<br>&nbsp;&nbsp;&nbsp;&nbsp;4.1.2. Hệ thống đóng hộp thoại xác nhận và giữ nguyên trạng thái tài khoản.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 1. |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình quản lý tài khoản trong mục "Cấu hình Cài đặt & Phân quyền". |
| **Hậu điều kiện** | - Trạng thái của tài khoản (Đang hoạt động / Đã khóa) được cập nhật vào CSDL.<br>- Tài khoản bị khóa sẽ không thể đăng nhập vào hệ thống. |

| **Use Case ID** | **UC 7.2.1** |
| :--- | :--- |
| **Tên Use Case** | **Thêm gói tập** |
| **Tóm tắt** | Cho phép Admin thêm mới một gói tập vào danh mục gói tập của hệ thống. |
| **Dòng sự kiện chính** | 1. Admin chọn "Thêm gói tập" trên màn hình Quản lý danh mục gói tập.<br>2. Hệ thống hiển thị biểu mẫu nhập thông tin gói tập mới.<br>3. Admin nhập thông tin chi tiết của gói tập (tên gói, thời hạn/số buổi, đơn giá, khung giờ tập, mô tả).<br>4. Admin nhấn nút "Hoàn tất" (hoặc "Lưu").<br>5. Hệ thống kiểm tra dữ liệu, lưu gói tập mới vào CSDL và hiển thị thông báo "Thêm gói tập thành công". |
| **Dòng sự kiện phụ** | **5.1. Dữ liệu gói tập không hợp lệ hoặc trùng tên:**<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.1. Hệ thống phát hiện tên gói tập đã tồn tại hoặc thông số giá tiền/thời hạn nhập sai định dạng và hiển thị thông báo lỗi chi tiết.<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.2. Hệ thống giữ lại thông tin gói tập mới do Admin vừa nhập.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 3. |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình "Quản lý danh mục gói tập" trong mục Cấu hình. |
| **Hậu điều kiện** | - Thông tin gói tập mới được lưu vào CSDL và hiển thị trong danh mục gói tập của hệ thống. |

Admin chỉnh sửa các thông tin cần thiết (tên gói, đơn giá, thời hạn, trạng thái kinh doanh...).<br>4. Admin nhấn nút "Lưu thay đổi".<br>5. Hệ thống kiểm tra tính hợp lệ, cập nhật thông tin gói tập vào CSDL và hiển thị thông báo "Cập nhật gói tập thành công". |
| **Dòng sự kiện phụ** | **5.1. Dữ liệu cập nhật không hợp lệ hoặc trùng tên:**<br>&nbsp;&nbsp;&nbsp;&nbsp;5.1.1. Hệ thống giữ lại thông tin Admin vừa chỉnh sửa.<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 3. |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình "Quản lý danh mục gói tập" và gói tập cần sửa đã tồn tại. |
| **Hậu điều kiện** | - Thông tin mới của gói tập được cập nhật vào CSDL. |

| **Use Case ID** | **UC 7.2.3** |
| :--- | :--- |
| **Tên Use Case** | **Xóa gói tập** |
| **Tóm tắt** | Cho phép Admin xóa một gói tập chưa phát sinh dữ liệu giao dịch ra khỏi danh mục hệ thống. |
| **Dòng sự kiện chính** | 1. Admin chọn một gói tập trong danh mục và nhấn nút "Xóa".<br>2. Hệ thống hiển thị hộp thoại cảnh báo và yêu cầu xác nhận xóa.<br>3. Admin nhấn "Xác nhận".<br>4. Hệ thống kiểm tra ràng buộc dữ liệu, xóa gói tập khỏi CSDL và hiển thị thông báo "Xóa gói tập thành công". |
| **Dòng sự kiện phụ** | **4.1. Ràng buộc dữ liệu (Gói tập đang có hội viên sử dụng):**<br>&nbsp;&nbsp;&nbsp;&nbsp;4.1.1. Hệ thống phát hiện gói tập đang có hội viên đăng ký sử dụng hoặc đã phát sinh hóa đơn.<br>&nbsp;&nbsp;&nbsp;&nbsp;4.1.2. Hệ thống từ chối xóa và hiển thị thông báo lỗi kèm gợi ý chuyển trạng thái gói tập sang "Ngừng kinh doanh".<br>&nbsp;&nbsp;&nbsp;&nbsp;Quay lại bước 1. |
| **Tiền điều kiện** | - Admin đã đăng nhập thành công bằng tài khoản có quyền Quản trị cao nhất.<br>- Admin đang truy cập tại màn hình "Quản lý danh mục gói tập". |
| **Hậu điều kiện** | - Gói tập bị xóa khỏi CSDL (nếu chưa có hội viên đăng ký) và không còn hiển thị trên danh mục. |
